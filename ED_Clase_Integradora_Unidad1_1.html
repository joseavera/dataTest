Punto de partida
Cuatro estructuras, una decision en comun

A lo largo de esta unidad construimos cuatro herramientas: el arreglo, que ofrece acceso directo a cambio de tamano fijo; la lista enlazada, que sacrifica el acceso directo por flexibilidad de tamano; la pila, que impone LIFO para resolver problemas de retroceso; y la cola, que impone FIFO para resolver problemas de turnos.

Ninguna de las cuatro es superior a las demas en terminos absolutos. Cada una es la respuesta correcta a una pregunta especifica: ?en que orden necesito acceder a los datos, y que tan seguido cambia su cantidad?

Esta sesion no introduce conceptos nuevos. Su proposito es que practiques la decision mas importante de todo el curso hasta ahora: elegir la estructura correcta antes de escribir una sola linea de codigo.

El sistema que vamos a construir

Trabajaremos sobre un sistema de biblioteca escolar con cuatro requerimientos distintos: un catalogo de 5 categorias fijas, una lista de socios que se inscriben y se dan de baja, una fila de espera para libros muy solicitados, y un historial de prestamos para poder deshacer el ultimo registro en caso de error.

Cada requerimiento se resuelve con una estructura distinta de la unidad. Al final del programa tendras un sistema funcional que demuestra el dominio completo de Unidad 1.

Codigo en C#
Sistema completo de la biblioteca

El siguiente programa implementa los cuatro modulos en un solo archivo. Cada modulo usa la estructura definida en la matriz de decision. Lee los comentarios: explican por que se eligio cada una.

SistemaBiblioteca.cs C# 
using System;
using System.Collections.Generic;

class Program
{
    // ── MODULO 1: Catalogo ─────────────────────────────────────────
    // Array: 5 categorias fijas, nunca cambian. Acceso directo por indice.
    static string[] categorias = {
        "Ficcion", "Ciencia", "Historia", "Arte", "Infantil"
    };

    // ── MODULO 2: Socios ───────────────────────────────────────────
    // LinkedList: la lista crece y encoge con cada inscripcion o baja.
    static LinkedList<string> socios = new LinkedList<string>();

    // ── MODULO 3: Fila de espera ───────────────────────────────────
    // Queue: FIFO. El primero en pedir el libro es el primero en recibirlo.
    static Queue<string> filaEspera = new Queue<string>();

    // ── MODULO 4: Historial de prestamos ───────────────────────────
    // Stack: LIFO. Permite deshacer siempre el ultimo registro.
    static Stack<string> historial = new Stack<string>();

    static void Main()
    {
        Console.WriteLine("==========================================");
        Console.WriteLine("  SISTEMA DE BIBLIOTECA — UNIDAD 1");
        Console.WriteLine("==========================================");

        MostrarCatalogo();
        Console.WriteLine();

        InscribirSocio("Ana Ramirez");
        InscribirSocio("Luis Torres");
        InscribirSocio("Sofia Gomez");
        DarDeBajaSocio("Luis Torres");
        MostrarSocios();
        Console.WriteLine();

        PedirLibro("Ana Ramirez", "Cien anios de soledad");
        PedirLibro("Sofia Gomez", "Cien anios de soledad");
        PedirLibro("Marco Diaz",  "Cien anios de soledad");
        EntregarSiguiente();
        Console.WriteLine();

        RegistrarPrestamo("Ana Ramirez: Cien anios de soledad");
        RegistrarPrestamo("Sofia Gomez: El Principito");
        DeshacerUltimoPrestamo();
        MostrarHistorial();
    }

    // ── Funciones del modulo Catalogo (Array) ──────────────────────
    static void MostrarCatalogo()
    {
        Console.WriteLine("--- Catalogo de categorias ---");
        for (int i = 0; i < categorias.Length; i++)
            Console.WriteLine($"  [{i}] {categorias[i]}");
    }

    // ── Funciones del modulo Socios (LinkedList) ───────────────────
    static void InscribirSocio(string nombre)
    {
        socios.AddLast(nombre);
        Console.WriteLine($"Socio inscrito: {nombre}");
    }

    static void DarDeBajaSocio(string nombre)
    {
        if (socios.Contains(nombre))
        {
            socios.Remove(nombre);
            Console.WriteLine($"Socio dado de baja: {nombre}");
        }
    }

    static void MostrarSocios()
    {
        Console.WriteLine("--- Socios activos ---");
        foreach (string s in socios)
            Console.WriteLine($"  {s}");
        Console.WriteLine($"Total: {socios.Count}");
    }

    // ── Funciones del modulo Fila de espera (Queue) ────────────────
    static void PedirLibro(string solicitante, string titulo)
    {
        filaEspera.Enqueue(solicitante);
        Console.WriteLine($"{solicitante} solicito: {titulo}");
    }

    static void EntregarSiguiente()
    {
        if (filaEspera.Count > 0)
        {
            string siguiente = filaEspera.Dequeue();
            Console.WriteLine($"Libro entregado a: {siguiente}");
            Console.WriteLine($"En espera todavia: {filaEspera.Count}");
        }
    }

    // ── Funciones del modulo Historial (Stack) ─────────────────────
    static void RegistrarPrestamo(string registro)
    {
        historial.Push(registro);
        Console.WriteLine($"Prestamo registrado: {registro}");
    }

    static void DeshacerUltimoPrestamo()
    {
        if (historial.Count > 0)
        {
            string deshecho = historial.Pop();
            Console.WriteLine($"Prestamo deshecho: {deshecho}");
        }
    }

    static void MostrarHistorial()
    {
        Console.WriteLine("--- Historial (mas reciente primero) ---");
        foreach (string h in historial)
            Console.WriteLine($"  {h}");
    }
}
Nota de arquitectura Observa que cada estructura se declara como static a nivel de clase, no dentro de Main(). Esto permite que todas las funciones del programa accedan y modifiquen el mismo catalogo, la misma lista de socios, la misma fila y el mismo historial.

Cierre de la unidad
Lo que sigue: estructuras no lineales

Las cuatro estructuras de esta unidad comparten una propiedad: son lineales. Cada elemento tiene como maximo un predecesor y un sucesor. Esa linealidad facilita razonarlas, pero tambien limita lo que pueden representar de forma eficiente.

En la Unidad 2 trabajaremos con arboles: estructuras donde un elemento puede tener varios sucesores. Esto permitira representar jerarquias, busquedas mas eficientes que recorrer una lista completa, y problemas como el sistema de archivos de una computadora o el arbol genealogico de una familia.

Puente conceptual Asi como un nodo de LinkedList apunta a un solo siguiente nodo, un nodo de arbol apuntara a varios hijos. La logica de punteros que ya dominas en esta unidad es exactamente la base que necesitaras para entender arboles.
