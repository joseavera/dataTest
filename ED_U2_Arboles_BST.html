Puente desde la Unidad 1
De estructuras lineales a no lineales

Todas las estructuras de la Unidad 1 comparten una propiedad: son lineales. En un arreglo, en una lista enlazada, en una pila o en una cola, cada elemento tiene a lo sumo un predecesor y un sucesor. La informacion se organiza como una fila.

Esa linealidad funciona bien cuando la cantidad de datos es pequena. Pero si necesitas buscar un valor en una lista de un millon de elementos, tendras que recorrer, en el peor caso, el millon completo. Esto se llama busqueda lineal y su costo es O(n).

El arbol binario de busqueda rompe esa linealidad: organiza los datos de forma jerarquica y garantiza que, si el arbol esta bien construido, encontrar cualquier valor requiere a lo sumo log2(n) comparaciones. Para un millon de elementos, eso significa como maximo 20 comparaciones.

La analogia del diccionario

Cuando buscas una palabra en un diccionario fisico, no comienzas desde la letra A y avanzas pagina por pagina. Abres por la mitad: si tu palabra esta antes, descartaste la mitad del libro; si esta despues, descartaste la otra mitad. Repites hasta encontrarla.

Eso es exactamente lo que hace un BST: en cada nodo toma una decision binaria — izquierda o derecha — y con cada decision descarta aproximadamente la mitad de los datos restantes. La busqueda no recorre todo: navega.

Tema 2.1 — Concepto
Terminologia del arbol
BST construido con la secuencia: 50, 30, 70, 20, 40, 60, 80
Raiz
El nodo superior del arbol. Todos los demas nodos descienden de el. En el ejemplo: 50.
Nodo
Cada elemento del arbol. Contiene un valor y referencias a hijo izquierdo e hijo derecho.
Hijo
Nodo que desciende directamente de otro. Un nodo binario tiene a lo sumo dos hijos.
Hoja
Nodo sin hijos. Sus referencias izquierda y derecha valen null. En el ejemplo: 20, 40, 60, 80.
Altura
Numero de niveles del arbol. Determina el costo de busqueda. En el ejemplo: altura = 3.
SubArbol
Cualquier nodo con sus descendientes forma un subarbol. El nodo 30 encabeza el subarbol izquierdo.
Tema 2.1 — Propiedad fundamental
La regla que define un BST
Propiedad de orden del BST
Para cualquier nodo N del arbol, se cumple siempre:

Todos los valores del subarbol izquierdo de N son menores que el valor de N.
Todos los valores del subarbol derecho de N son mayores que el valor de N.

Esta propiedad no aplica solo a la raiz: aplica a cada nodo individualmente. Verificarla en la raiz no garantiza que se cumpla en los nodos internos.
Verificacion en el ejemplo
Raiz 50: izquierda tiene {20, 30, 40}, todos menores. Derecha tiene {60, 70, 80}, todos mayores.

Nodo 30: izquierda tiene {20}, menor. Derecha tiene {40}, mayor.

La propiedad se cumple en cada nodo del arbol.
Por que importa esta propiedad
Al buscar un valor X, en cada nodo la comparacion elimina un subarbol completo. Si X es menor que el nodo actual, el subarbol derecho ya no se revisa. Cada comparacion reduce el problema a la mitad.
Conexion con la Unidad 1 El nodo de un BST es conceptualmente igual al nodo de un LinkedList: contiene un dato y referencias a otros nodos. La diferencia es que aqui hay dos referencias (izquierda y derecha) en lugar de una sola (siguiente).
Tema 2.1 — Operacion de insercion
Como se inserta un valor en el BST
1
Si el arbol esta vacio, el nuevo nodo se convierte en la raiz.
2
Compara el valor nuevo con el nodo actual. Si es menor, ve al hijo izquierdo. Si es mayor, ve al hijo derecho.
3
Si el hijo en esa direccion es null, inserta el nodo ahi. Si no es null, repite el paso 2 con ese hijo como nuevo nodo actual.
4
El proceso garantiza que la propiedad BST siempre se mantiene despues de cada insercion.

Traza de insercion para la secuencia: 50, 30, 70, 20, 40, 60, 80

Insertar 50: arbol vacio → 50 es la raiz.
Insertar 30: 30 < 50 → va al hijo izquierdo de 50.
Insertar 70: 70 > 50 → va al hijo derecho de 50.
Insertar 20: 20 < 50 → izquierda; 20 < 30 → hijo izquierdo de 30.
Insertar 40: 40 < 50 → izquierda; 40 > 30 → hijo derecho de 30.
Insertar 60: 60 > 50 → derecha; 60 < 70 → hijo izquierdo de 70.
Insertar 80: 80 > 50 → derecha; 80 > 70 → hijo derecho de 70.

Observacion El orden en que se insertan los valores determina la forma del arbol. La secuencia 50, 30, 70... produce un arbol equilibrado. Si hubieramos insertado 20, 30, 40, 50, 60, 70, 80 en ese orden, el arbol degeneraria en una lista enlazada hacia la derecha. Los arboles AVL y Heap de los temas siguientes resuelven este problema.
Codigo en C#
Ejemplo 1 — Definir la clase Nodo

Un BST en C# requiere primero definir que es un nodo. El nodo guarda el valor y dos referencias: una al hijo izquierdo y otra al hijo derecho. Si no hay hijo, la referencia vale null.

Nodo.cs C# 
// Un nodo de BST contiene tres cosas:
// 1. El valor que almacena
// 2. Una referencia al hijo izquierdo (menor)
// 3. Una referencia al hijo derecho (mayor)
class Nodo
{
    public int  Valor;
    public Nodo Izquierdo;
    public Nodo Derecho;

    public Nodo(int valor)
    {
        Valor      = valor;
        Izquierdo  = null; // sin hijo izquierdo al crearse
        Derecho    = null; // sin hijo derecho al crearse
    }
}
Conexion directa Compara este nodo con el de LinkedList: aquel tenia Valor y un solo Siguiente. Este tiene Valor, Izquierdo y Derecho. La logica de punteros es exactamente la misma; solo cambia cuantos hay.

Ejemplo 2 — Clase BST con insercion e InOrder
BST.cs C# 
class BST
{
    private Nodo raiz = null;

    // ── Insertar ────────────────────────────────────────────────────
    public void Insertar(int valor)
    {
        raiz = InsertarRec(raiz, valor);
    }

    private Nodo InsertarRec(Nodo nodo, int valor)
    {
        // Caso base: posicion libre, crear el nuevo nodo aqui
        if (nodo == null)
            return new Nodo(valor);

        // Comparar y bajar por el subarbol correcto
        if (valor < nodo.Valor)
            nodo.Izquierdo = InsertarRec(nodo.Izquierdo, valor);
        else if (valor > nodo.Valor)
            nodo.Derecho   = InsertarRec(nodo.Derecho, valor);
        // Si valor == nodo.Valor no se inserta (sin duplicados)

        return nodo;
    }

    // ── Recorrido InOrder: Izquierdo - Raiz - Derecho ───────────────
    // Produce los valores en orden ASCENDENTE por la propiedad BST
    public void InOrder()
    {
        InOrderRec(raiz);
        Console.WriteLine();
    }

    private void InOrderRec(Nodo nodo)
    {
        if (nodo == null) return;

        InOrderRec(nodo.Izquierdo);   // visita el subarbol izquierdo
        Console.Write(nodo.Valor + " "); // imprime el nodo actual
        InOrderRec(nodo.Derecho);    // visita el subarbol derecho
    }
}
Codigo en C#
Ejemplo 3 — Programa completo ejecutable
Program.cs C# 
using System;

class Nodo
{
    public int  Valor;
    public Nodo Izquierdo, Derecho;
    public Nodo(int v) { Valor = v; }
}

class BST
{
    private Nodo raiz;

    public void Insertar(int v) => raiz = Ins(raiz, v);

    private Nodo Ins(Nodo n, int v)
    {
        if (n == null) return new Nodo(v);
        if (v < n.Valor) n.Izquierdo = Ins(n.Izquierdo, v);
        else if (v > n.Valor) n.Derecho = Ins(n.Derecho, v);
        return n;
    }

    public void InOrder()
    {
        IO(raiz);
        Console.WriteLine();
    }

    private void IO(Nodo n)
    {
        if (n == null) return;
        IO(n.Izquierdo);
        Console.Write(n.Valor + " ");
        IO(n.Derecho);
    }
}

class Program
{
    static void Main()
    {
        BST arbol = new BST();

        int[] valores = { 50, 30, 70, 20, 40, 60, 80 };

        Console.WriteLine("Insertando: 50, 30, 70, 20, 40, 60, 80");
        foreach (int v in valores)
            arbol.Insertar(v);

        Console.Write("InOrder: ");
        arbol.InOrder();
        // Salida: 20 30 40 50 60 70 80  (orden ascendente)
    }
}
Por que InOrder produce orden ascendente El recorrido InOrder visita siempre: subarbol izquierdo (todos menores) → nodo actual → subarbol derecho (todos mayores). La propiedad BST garantiza que este patron produce los valores de menor a mayor sin excepcion.
