Punto de partida
De las pilas a las colas

En la sesion anterior estudiamos la pila (Stack<T>), cuya regla fundamental es LIFO: el ultimo elemento en ingresar es el primero en salir. Esa propiedad la hace ideal para historiales de acciones, navegacion hacia atras y evaluacion de expresiones.

Hoy presentamos su opuesto exacto: la cola. En una cola el primer elemento en ingresar es el primero en salir. El orden de llegada se respeta de manera estricta. Esta propiedad, llamada FIFO, aparece en casi cualquier sistema que maneja turnos, solicitudes o mensajes.

La cola no reemplaza a la pila: cada una existe porque hay problemas que solo una de ellas resuelve correctamente. Al terminar esta sesion podras elegir entre ambas con criterio tecnico.

Analogia de la sesion

Imagina la fila de alumnos en la ventanilla de la cafeteria. El primero que llego es el primero en ser atendido. No importa cuantos lleguen despues: nadie puede saltarse a quien ya estaba esperando.

Eso es exactamente una cola en programacion: los elementos entran por un extremo (el fondo) y salen por el otro extremo (el frente). No hay acceso a posiciones intermedias ni posibilidad de insertar por el frente.

Tema 1.4 — Concepto
Principio FIFO
FIFO — First In, First Out
El primer elemento en ingresar a la cola es el primero en ser extraido. El orden de salida es identico al orden de entrada. Esta propiedad garantiza equidad y reproducibilidad en sistemas de atencion secuencial.
Comparacion inmediata con Stack
Stack opera siempre sobre el tope: el ultimo en entrar es el primero en salir. Queue opera sobre el frente: el primero en entrar es el primero en salir. Son principios opuestos aplicados al mismo concepto de coleccion lineal.

Tema 1.4 — Operaciones
Las cuatro operaciones fundamentales
Operacion Descripcion Analogia Costo
Enqueue() Agrega un elemento al fondo de la cola. La cola crece en uno. Un alumno nuevo se coloca al final de la fila. O(1)
Dequeue() Extrae y devuelve el elemento del frente. La cola decrece en uno. Se atiende al alumno del frente: abandona la fila. O(1)
Peek() Devuelve el elemento del frente sin extraerlo. La cola no cambia. Ver quien es el siguiente sin atenderlo todavia. O(1)
Count Propiedad que indica cuantos elementos contiene la cola en ese momento. Contar cuantos alumnos hay en la fila. O(1)
Error critico Llamar Dequeue() o Peek() sobre una cola vacia genera InvalidOperationException en tiempo de ejecucion. Siempre verificar Count > 0 antes de extraer o consultar el frente.
Codigo en C#
Ejemplo 1 — Declarar la cola y agregar elementos

La clase Queue<T> pertenece al espacio de nombres System.Collections.Generic, igual que Stack<T> y LinkedList<T>. La sintaxis de declaracion es identica; lo que cambia es el comportamiento.

Ejemplo1_Declaracion.cs C# 
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        // Declarar una cola de textos vacia
        Queue<string> fila = new Queue<string>();
        //    ^tipo        ^nombre      ^constructor: crea la cola vacia

        // Enqueue: agregar al FONDO. El primero que entra queda en el FRENTE.
        fila.Enqueue("Ana Ramirez");   // fila: Ana <- frente
        fila.Enqueue("Luis Torres");   // fila: Ana | Luis <- fondo
        fila.Enqueue("Sofia Gomez");   // fila: Ana | Luis | Sofia <- fondo
        fila.Enqueue("Marco Diaz");    // fila: Ana | Luis | Sofia | Marco <- fondo

        // Count: cantidad actual de elementos
        Console.WriteLine($"Alumnos en fila: {fila.Count}"); // 4
    }
}
Codigo en C#
Ejemplo 2 — Dequeue y Peek sobre la misma cola
Ejemplo2_DequeueYPeek.cs C# 
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        Queue<string> fila = new Queue<string>();
        fila.Enqueue("Ana Ramirez");
        fila.Enqueue("Luis Torres");
        fila.Enqueue("Sofia Gomez");
        fila.Enqueue("Marco Diaz");
        // Estado: Ana (frente) | Luis | Sofia | Marco (fondo)

        // Peek: ver el frente SIN extraerlo — Count no cambia
        string siguiente = fila.Peek();
        Console.WriteLine($"Siguiente: {siguiente}");          // Ana Ramirez
        Console.WriteLine($"Count tras Peek: {fila.Count}");    // 4 (no cambio)

        // Dequeue: extraer el frente — Count disminuye en 1
        string atendido = fila.Dequeue();
        Console.WriteLine($"Atendiendo: {atendido}");           // Ana Ramirez
        Console.WriteLine($"Count tras Dequeue: {fila.Count}"); // 3 (disminuyo)

        // Nuevo frente despues del Dequeue
        Console.WriteLine($"Nuevo frente: {fila.Peek()}");       // Luis Torres
    }
}
Peek() — solo consultar el frente
Devuelve el valor del frente. La cola permanece identica. Count no cambia. Util para tomar decisiones sobre el proximo elemento antes de extraerlo.
Dequeue() — extraer y devolver
Extrae el frente y lo devuelve. La cola pierde un elemento. Count disminuye en 1. El siguiente elemento pasa a ser el nuevo frente.
Codigo en C#
Ejemplo 3 — Programa completo con foreach
Ejemplo3_Completo.cs C# 
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        Queue<string> fila = new Queue<string>();

        fila.Enqueue("Ana Ramirez");
        fila.Enqueue("Luis Torres");
        fila.Enqueue("Sofia Gomez");
        fila.Enqueue("Marco Diaz");

        // foreach recorre del FRENTE al FONDO sin modificar la cola
        Console.WriteLine("=== Fila de atencion ===");
        foreach (string a in fila)
            Console.WriteLine($"  {a}");

        // Atender a todos en orden, verificando que la cola no este vacia
        Console.WriteLine("\n=== Atendiendo en orden ===");
        while (fila.Count > 0)
        {
            string turno = fila.Dequeue();
            Console.WriteLine($"Atendiendo: {turno}");
        }

        Console.WriteLine($"\nAlumnos restantes en fila: {fila.Count}"); // 0
    }
}
Nota foreach en una cola recorre del frente al fondo, en el mismo orden en que se insertaron los elementos. El ciclo while (fila.Count > 0) es el patron estandar para vaciar una cola de forma segura sin generar InvalidOperationException.

Las cuatro estructuras lineales

Con Queue completamos las cuatro estructuras lineales de la Unidad 1. La siguiente tabla resume cuando elegir cada una en funcion de las operaciones que el problema requiere con mayor frecuencia.

Criterio Array LinkedList<T> Stack<T> Queue<T>

Tamano fijo Si — ideal No aplica No aplica No aplica

Clave La pregunta que guia la eleccion es siempre la misma: ?en que orden necesito acceder a los datos? Si el orden no importa y el tamano es fijo: Array. Si cambia con frecuencia: LinkedList. Si siempre necesito el ultimo: Stack. Si siempre necesito el primero: Queue.

    Un sistema de impresion universitario: los trabajos se imprimen en el mismo orden en que se enviaron desde las computadoras del laboratorio.

    El boton de retroceso de un navegador web: al presionarlo regresa a la ultima pagina que visitaste.
